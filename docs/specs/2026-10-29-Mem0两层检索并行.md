# Mem0 两层检索并行

> 状态：已批准，实施中
> 日期：2026-10-29
> 父规格：`2026-10-29-流式链路资源与延迟治理.md`（R5 的后续）

## 1. 问题

`ChatLongMemoryService.search()` 现在是顺序 `await`：先 user 层，再 session 层。

```python
user_res = await self._client.search(query, filters={"user_id": ...}, top_k=n)
if session_id:
    session_res = await self._client.search(query, filters={..., "run_id": ...}, top_k=n)
```

两层只共享 `query` 这一个只读字符串，**没有任何依赖**：一层的结果不参与另一层的过滤条件。
实测 `memory` span p50 是 **1038ms**，与「两次往返之和」一致；这意味着 `MEM0_SEARCH_TIMEOUT_MS=1500`
这个预算，实际是在覆盖**两次**串行往返（正常一次约 400~600ms，余量只剩一次）。

父规格已把 classify 与 memory 并行（`bbbc9a4`），但 memory 内部这一层串行被留了下来 ——
它是同一根因在更小粒度上的残留。

## 2. 目标

| | 目标 | 判据 |
| --- | --- | --- |
| G1 | 两层同时发出，`memory` span 从「两次往返之和」降到「一次往返 + 抖动」 | 单测：两层各睡 0.3s 时总耗时 < 0.5s（串行为 0.6s） |
| G2 | 墙钟上限不变 | 1500ms deadline 仍覆盖整体，不是每层 1500ms |
| G3 | 单层失败不再拖空另一层 | 单测：user 层抛错时 session 层结果仍返回 |

**非目标**：改预算值、改 `MEM0_TOP_K`、加熔断/重试、改 `_pick_memories` 的解析口径、
改 `build_system_message` 的注入位置。

## 3. 需求

- **R1** 两层用 `asyncio.gather(..., return_exceptions=True)` 同时发出，外层仍是
  一个 `asyncio.timeout(self._timeout_s)`，语义从「共用 deadline」保持不变。
- **R2** 结果按**入参顺序**认层，不按完成顺序。`gather` 保序是能按下标取结果的前提；
  换 `as_completed` 就必须给每个请求带 tag，属无谓复杂化。
- **R3** 单层异常只降级该层并 WARN（写明是哪一层）；`CancelledError` 必须向上抛，
  不能把「请求被取消」伪装成「没有记忆」。
- **R4** 无 `session_id` 时只发一个请求，不为空会话层白跑一次。
- **R5** 超时日志仍打**生效**预算 `self._timeout_s`，不是配置值。

## 4. 行为变化（必须披露）

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 正常轮次 | 2 次往返串行 | 2 次往返并行，**省一次往返** |
| 超时轮次 | 第 1 层超时 → 第 2 层根本不发（1 次调用） | 两层**都已发出**（2 次调用） |
| 单层失败 | 整体返回空（两层都丢） | 只有失败那层为空 |

第二行是并行的必然代价：发出请求前无法预知整体会超时。若 Mem0 按调用计费，
**超时轮次会多计一次调用**。收益侧对应的是每一轮正常对话都省一次往返，
按实测约 400~600ms，量级远大于代价。

第三行是顺带修正：原实现的 docstring 写「任何异常只 WARN 并返回空」，
但实际是一层失败两层都空，与文档不符。本次一并改成符合既定意图的行为。

## 5. 接口

对调用方**零变化**：

```python
async def search(self, user_id: str, session_id: str | None, query: str) -> LongMemoryHits
```

新增模块级私有函数：

```python
def _layer_payload(raw: object, layer: str) -> dict[str, Any]
```

把 `gather(return_exceptions=True)` 的 `dict | BaseException` 归一成 payload，
并把「哪一层失败」写进日志。

## 6. 边界与失败模式

| 情况 | 行为 |
| --- | --- |
| `MEM0_API_KEY` 未配 | 直接返回空，不发任何请求（不变） |
| `asyncio.timeout(None)` | 不限，两层仍并行（不变） |
| 外层超时 | `gather` 被取消时子任务一并取消，无「Task was destroyed」泄漏 |
| 两层都抛异常 | 返回空，两条 WARN（原为一条） |
| `session_id` 为空串 | 视为无会话层（`if session_id` 的既有语义） |
| 平台返回结构异常 | `_pick_memories` 逐层兜底，退化为空列表（不变） |
