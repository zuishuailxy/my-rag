**同文件拆 hunk 的稳办法（比「临时还原 → 提交主体 → 写回」更轻，全程不改文件内容，只动索引）**：

1. `git diff -- <file> > /tmp/all.patch`，用脚本按 `^@@` 切出各 hunk，再按语义分组成
   两份 patch（header 原样保留；每个 hunk 自带完整上下文，git apply 会自动定位偏移）；
2. `git apply --cached --check <p1>` 校验 → `git apply --cached <p1>` 把**第 1 个提交的
   hunk** 放进索引 → `git diff --cached -- <file>` 复核只含该语义；
3. `git commit -F <msg>`（**不加 `-a`**，其余文件保持未暂存）；
4. 第 2 个提交直接 `git add <file>` —— 工作区 = 全部改动、HEAD = 已含第 1 批，
   `git diff` 自然只剩第 2 批 hunk，无需再切 patch。

配套校验：`git show :<path> > /tmp/x.py` 把**暂存版本**导出后 `py_compile`，确认第 1 个
提交自身语法自洽（索引态与工作区态不同，mypy 跑的是工作区，验证不到索引态）。
