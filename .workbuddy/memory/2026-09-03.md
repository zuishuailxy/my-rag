### 修掉的一处真实缺陷
`Team.updated_at` **缺 `onupdate=func.now()`** —— TS 是 `@UpdateDateColumn`（UPDATE 自动刷新），
Python 原先只有 `server_default`。实测证据：
- 裸 SQL `UPDATE kh_team SET team_name=...`（不含 updated_at）→ updated_at **纹丝不动**
  → 证明 init.sql 只有 `DEFAULT NOW()`、**无触发器**，ORM onupdate 是唯一机制。
- ORM 路径改字段后 → `UPDATE kh_team SET ..., updated_at=now()` → 跨事务确实刷新。
已补 `onupdate=func.now()` 并加注释（含 MissingGreenlet 提醒：commit 后读该属性要先
`await session.refresh()`）。

### 关键保真点 / 刻意差异
- **同码不查重**：TS create 无编码查重（kh_team 也无 unique 约束）→ 冒烟实测 201 保真。
- **create 不校验 leaderId/parentId 存在**（TS 同样不查，悬空引用如实保留）。
- **delete**：有未删子团队 400「存在子团队，无法删除」；软删 team 后**硬删**成员关联。
  TS 分 save+delete 两步，Python 合并单事务提交（语义一致，原子性更强）。
- **addMembers**：用户缺一 404「部分用户不存在」；已存在关联幂等跳过；memberRole 恒 'member'；
  TS 逐个 findOne+save（N 次查询），Python 同款保真不合并批量。空数组 no-op（In([]) 恒假条件）。
- **getTree**：仅 status=1 未删，sort ASC / created_at ASC；rootOnly=true 返回根节点
  （TS 不带 children 键，Python 响应模型统一补 children:[]，已注释为刻意差异）。
- **page 排序**：sort ASC + **created_at DESC**（与 permission 的 ASC 不同，保真）。
- **tree 是公开接口**：TS @Public()；Python auth_route 的 @public+@roles 组合语义是 roles 优先，
  故只标 @public 不标 @roles（若 TS RolesGuard 实际要求管理员，再补）。其余 8 端点双层守卫
  @roles(ADMIN) + require_permission("system:team")。
- **路由顺序**：/page、/tree 字面量段注册在 /{team_id} 之前。
- **状态码**：POST create 与 addMembers → 201（NestJS @Post 默认），其余 200；
  addMembers/removeMembers 请求体是**裸字符串数组**（@Body() userIds: string[]），非对象包裹。
- update 对显式 null 的处理：TS IsOptional 放行 null 写入列，Python None=未传不改动
  （清空字段传空串 ""），已注释。
