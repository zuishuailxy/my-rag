### ⚠️ 本轮最重要的发现：mypy 增量缓存让门禁假绿

- 本批改动跑 `mypy app/`（默认增量）报 **10 error**，其中 3 个不在本批 diff 里。
- 用 `git worktree add /tmp/myrag-head HEAD` 拉 HEAD 副本、用主仓 venv 的 mypy 单独全量跑
  → **HEAD 本身就有那 3 个错误**：
  - `chat_query_rewrite.py:731/733` `"None" not callable`（`Optional[Any]` 不可调用）
  - `ai_stream.py:635` `create_turn_agent` 收到 `ChatRoutePlan`，形参却标 `dict[str, Any]`
- 结论：**默认增量只重查变更模块，未改动文件的存量错误不会被报出来**。此前几次
  「108 / 110 files 0 issue」的绿灯里都藏着这 3 个。
- ✅ 修正做法：提交前跑 **`mypy --no-incremental app/`**。实测全量 **不 OOM**
  （mem0 的 `follow_imports=skip` override 之后），耗时也可接受。此前「必须用增量跑以免
  OOM」的经验只对 override 之前成立，现已过时。
- 复核手段可复用：`git worktree add <tmp> HEAD` + 主仓 venv 的 mypy 在 worktree 里跑，
  **零风险拿到「HEAD 是否本来就红」的确定结论**（不动工作区、不用 stash、不切分支）；
  用完 `git worktree remove --force`（顺带删了目录）。
