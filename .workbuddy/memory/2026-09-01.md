## PATCH「全字段必填」排查 + Swagger 示例治理
- 现象：用户看 Swagger 里 `PATCH /documents/{id}` 的 Example Value 列出了全部 12 个字段且值全是 `"string"`，以为全必填；原样提交报 `400 Invalid categoryId: string`。
- **结论：没有任何字段必填**。三处证据——① `DocumentUpdate.model_json_schema()` 无 `required`；② OpenAPI `components.schemas.DocumentUpdate.required = None`；③ 实测 `PATCH {}` → 200（只刷 `updated_at`），`PATCH {"summary":"..."}` → 200 且 title 不变、SQL 只 `SET summary`。
- 关键认知：**Swagger UI 的 Example Value 面板会把 schema 里每个 property 都生成占位值**（string→`"string"`，IntEnum→第一个成员 `0`），与 required 无关；必填字段只在 Schema 面板挂红色 `*`。`requestBody.required=true` 指的是「请求体本身要传」（至少 `{}`），不是每字段必填。
- **因果链闭环**：Swagger 自动示例 → `categoryId:"string"` → 上一轮 500 的触发器就是它，收敛后变成 400。用户提交方式就是直接点 Execute。

## 鉴权守卫实现（route_class 方案，替代中间件）
- 用户问「guard 是不是可以用中间件实现」并贴出 TS 的 jwt-auth.guard.ts / jwt.strategy.ts / roles.guard.ts / 三个 decorator 源码。
- **实测否定中间件方案**：BaseHTTPMiddleware 是纯 ASGI 中间件，运行在路由匹配之前，`scope` 里只有 path（实测 `has_route=False`、`route=None`），读不到 `@Public()` 打在 endpoint 上的标记 → 只能退化成硬编码路径白名单，与路由定义分离易漂移。route_class 实测能读到 endpoint 属性（`public=True` / `MISSING`）。
- 经 AskUserQuestion 选型：① 用 route_class 全局守卫；② documents/health 是否纳入让我判断 → 我判断**全部纳入、health 豁免**，理由：默认全拦语义下「暂不纳入」反而要主动给每个 documents 路由打 `@public()`，等于明文记录一批已知不安全窗口，散落多文件、后续漏删即永久裸奔；而「什么都不做 = 受保护」是 fail-safe。
