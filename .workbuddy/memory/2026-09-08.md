## 关键实现决策

- **append_turn 必须显式赋 `updated_at = func.now()`**：标题不变且无字段变更时 SQLAlchemy 不发 UPDATE，updated_at 会停在上轮；TS 靠 `new Date()` 强制 save() 触发更新。仅靠 ORM onupdate 不够（onupdate 只在真的有 UPDATE 语句时生效）。
- 删除顺序与 TS 保真：先删消息再删会话（DDL 有 CASCADE 但不依赖库级）。
- QuerySessionRequest 的 page/pageSize 补了上下界（page≥1，pageSize 1~100）——TS 源未贴、按项目分页惯例收紧，已注释文档化。
- FastAPI 语法坑：**无默认值的 Annotated Depends 参数必须放在带默认值的 Query 参数之前**，否则 SyntaxError。

## Git 语义化提交：按 hunk 拆分 + 一次踩坑

- 提交序列（6 个）：fix(rerank) → feat(retrieval) → fix(config) → feat(ai 流式+Tavily) → feat(frontend 流式渲染) → docs(memory)。
- **按 hunk 拆分混主题文件**（config.py 同时含 RAG_MIN_SCORE / OPENAI_API_KEY 去重 / 流式配置）：`git diff file > /tmp/x.patch` → python 按 `@@` 切分并**重算 hunk 头行数** → `git apply --cached --check` 校验 → `git apply --cached` 只进索引，工作区保持完整。
- ⚠️ 踩坑：按行过滤时漏删多行注释的第二行，提交留下孤立注释；随后用 `git checkout HEAD -- file` 想撤销暂存，**结果把工作区回退到 HEAD（含错误提交内容）**，丢掉尚未提交的 4 行配置。教训：撤暂存用 `git reset HEAD -- file`，`git checkout HEAD -- file` 是丢弃工作区改动（危险）。
- 正确补救：先把文件手工改成「只含该提交内容」→ `git add` + `git commit --amend -F -` 修正上一个提交 → 再把剩余改动加回工作区（用 `git rev-parse HEAD:file` 比对 blob 校验与原始版本一致）。
- 提交信息里的前端改动必须核对 diff 后再写，不可凭推断（已核对 useChat/@ai-sdk/react/api 路径/data-session 处理）。
