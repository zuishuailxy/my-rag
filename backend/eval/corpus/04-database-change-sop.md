# 数据库变更管理规范（SOP）

维护团队：平台工程部 · DBA 组　文档编号：SOP-PE-2026-007　版本：v1.3（2026-03-15）

## 1. 目的与范围

本规范定义生产环境数据库变更（DDL / DML / 参数调整）的实施流程，确保变更可审计、可回滚。适用于平台工程部负责的所有 MySQL、PostgreSQL 与 Redis 实例。

数据库变更负责人为 DBA 值班工程师；业务侧产品经理确认业务低峰窗口；安全部对涉及敏感字段的变更做合规抽检。

## 4. 变更前检查（T-1 日）

须在变更日前一天 17:00 前完成：

1. SQL 审核：变更语句已通过 SQL 审核平台，无全表扫描、无锁表风险。
2. 预发验证：在预发库执行并验证；报告上传知识库。
3. 备份确认：变更前已完成备份，备份集可恢复性已验证。
4. 通知：通过企业微信向「数据库变更群」发送窗口说明。

若 SQL 审核未通过，DBA 值班工程师有权驳回变更。

## 5. 执行与回滚

5.1 变更单创建：在 Jira 项目 PE-DB 创建变更单，关联 SQL 审核单号。

5.2 灰度验证：先在只读从库执行并观察 30 分钟，确认无异常再上主库。

监控依赖 Prometheus + Grafana；核心指标：慢查询数、主从延迟、连接数。

5.3 回滚条件：**慢查询 P99 超过 3 秒**，或**主从延迟超过 30 秒**，立即触发回滚：执行预先准备的 down 脚本，并通知产品经理评估是否对外公告。

5.4 数据修复：DML 误操作导致的回滚须在 2 小时内完成，并保留现场记录。

## 6. 变更后

DBA 组在每周一 10:00 站会上回顾上周变更事件。变更单状态在 Jira 关闭；导致故障的变更须 48 小时内 提交复盘文档至知识库。
